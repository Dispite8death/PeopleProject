# ПОКЕМОН · первый этап

Локальная университетская платформа заявок о помощи и мероприятиях. PHP-шаблон, адаптивный интерфейс на русском и демонстрационный источник данных. Бэкенд бизнес-правил остаётся вашей частью проекта.

Исходное задание сохранено в [docs/stage1-brief.txt](docs/stage1-brief.txt); реализованное состояние, решения и оставшиеся вопросы описаны здесь и в `docs/`, чтобы контекст следующей работы оставался в проекте.

**Локальный адрес: http://127.0.0.1:8080**

## Запуск и остановка

Откройте PowerShell в папке проекта. После перезагрузки Windows выполните:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\start.ps1
```

Остановка и состояние:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\stop.ps1
powershell -ExecutionPolicy Bypass -File .\scripts\status.ps1
```

Повторный start не создаёт дубликатов. Скрипты проверяют PID, путь исполняемого файла и время создания процесса; nginx останавливается по собственному pid-файлу, MariaDB — штатной командой shutdown. Чужие процессы и службы не останавливаются. Если порт занят чужим процессом, запуск завершится с объяснением.

Используются только `127.0.0.1`: HTTP **8080**, FastCGI **9070**, MariaDB **3307**. Адреса/порты сохранены в `.local/settings.json` и соответствующих локальных конфигурациях. В первом setup выбираются свободные порты; после настройки они сохраняются. Для смены порта согласованно измените settings.json и nginx.conf/my.ini/config/local.json; остановите проект перед изменением.

Особенность Windows: nginx не смог открыть путь с кириллицей и коротким именем 8.3. Поэтому скрипты создают **псевдодиск P:**, указывающий ровно на эту папку. Данные не копируются. Привязка восстанавливается при следующем запуске, её идентичность проверяется Unicode Win32 API; занятый чужой диск не переназначается. Выбранная буква хранится в `.local/drive.json`. При первом запуске на другой машине выбирается свободная буква P–Z. Если сохранённая буква уже занята, скрипт остановится; смена буквы требует обновления локальных путей. Не удаляйте привязку при работающих процессах.

Системные службы не устанавливаются, PATH и настройки других проектов не меняются. Администратор Windows для обычного запуска не требуется. `-ExecutionPolicy Bypass` применяется только к этому запуску PowerShell, не меняет постоянную политику компьютера.

## Что установлено и проверено 31.10.2026

- Windows x64; Microsoft Visual C++ Runtime x64 **14.51.36247.00** уже был установлен.
- **PHP 8.5.12**, официальный пакет **8.5.12-1 NTS VS17 x64**, через `php-cgi.exe`/FastCGI.
- **nginx 1.31.8**, официальная Windows-сборка **x86**. Разрядность бинарника проверена по PE-заголовку; она совместима с x64 Windows и не мешает отдельному x64 PHP через FastCGI.
- **MariaDB 11.8.9 x64**, InnoDB. База `pokemon_local`, пользователь приложения `pokemon_app@127.0.0.1`, кодировка соединения `utf8mb4`, предметных таблиц **0**.
- Расширения PHP: `pdo_mysql`, `mbstring`, `openssl`, `curl` плюс встроенные модули. `phpinfo()` через сайт не публикуется.
- Node.js используется только для дополнительных проверок JS, для запуска сайта npm/Node не нужны. Сборки фронтенда и внешних CDN нет.

Бинарники находятся в `.local/runtime/`, архивы — в `.local/downloads/`. Всё локальное окружение исключено из Git. PHP и MariaDB сверены с SHA-256 официальных источников; SHA-256 загруженного по HTTPS nginx закреплён для повторной установки. Это контроль повторяемости, а не отдельная проверка PGP-подписи nginx.

Официальные источники: [nginx Windows](https://nginx.org/en/docs/windows.html), [nginx downloads](https://nginx.org/en/download.html), [PHP Windows](https://www.php.net/downloads.php?os=windows), [установка PHP](https://www.php.net/manual/en/install.windows.manual.php), [PDO MySQL](https://www.php.net/manual/en/ref.pdo-mysql.php), [MariaDB downloads](https://mariadb.org/download/), [API загрузок MariaDB](https://mariadb.org/downloads-rest-api/).

При повторном разворачивании этой версии исходников на чистой машине:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\setup.ps1
powershell -ExecutionPolicy Bypass -File .\scripts\start.ps1
```

Setup скачивает закреплённые официальные архивы, проверяет суммы, инициализирует собственную БД и генерирует случайные локальные пароли. При существующей конфигурации ничего не переустанавливает. Не удаляйте `.local` ради повторной установки: там база данных. Перед будущим переносом нужно отдельно сохранить БД и локальную конфигурацию. Чистую повторную установку на другой машине в рамках этого этапа не проверяли.

## Структура

- `public/` — единственный web root: `index.php`, CSS, JS и значок проекта.
- `templates/layout.php` — общий PHP-шаблон; в браузер попадает только безопасная клиентская конфигурация.
- `app/bootstrap.php` — загрузка локальных параметров; `app/database.php` — PDO.
- `public/assets/js/app.js` — экраны, формы, маршрутизация разделов и обработчики.
- `public/assets/js/ui.js` — общие элементы, экранирование текста, даты и диалоги.
- `public/assets/js/data-source.js` — выбор demo/http; `demo-provider.js` и `seed.js` — явно демонстрационные данные; `http-provider.js` — сетевой адаптер.
- `config/example.json` — пример без секретов; `config/local.json` — реальные локальные пароли, вне Git и web root.
- `config/nginx.conf.template`, `config/php.ini.template` — переносимые образцы; `.local/nginx.conf`, `.local/php.ini`, `.local/my.ini` — рабочие конфигурации.
- `.local/admin.ini` — пароль административной учётной записи только для обслуживания локальной БД. Приложение использует отдельного пользователя с правами только на `pokemon_local.*`.
- `.local/logs/` — nginx access/error, PHP error, MariaDB и stdout/stderr процессов. Старые записи первоначальной настройки сохраняются как диагностика.
- `.local/data/mariadb/` — файлы базы; `.local/run/` — идентификаторы процессов и блокировка управления.
- `scripts/` — установка, запуск, остановка, состояние и проверки; `tests/demo.test.js` — содержательные проверки поведения демо.

Не передавайте `.local/` и `config/local.json` в публичные архивы или Git. Публичный сервер отдаёт только public; запросы к конфигурации, служебным файлам, скрытым путям и другим PHP-файлам отклоняются.

## Подключение вашего бэкенда

1. Согласуйте [проект API](docs/api-contract.md) и [сущности](docs/data-model.md).
2. Реализуйте серверные методы и авторизацию; замените заглушку `/api/` в nginx.
3. В `config/local.json` установите `mode: "http"` и нужный `apiBase`.
4. При необходимости адаптируйте DTO в `http-provider.js`, сохранив интерфейс методов для страниц.

Полный перечень точек подключения и открытых вопросов — [следующий этап](docs/next-stage.md). Серверный источник не переключается на демо при ошибках. Настоящие авторизация, рассылки, интеграция расписания, транзакционная запись и автоматический добор пока отсутствуют. Политика добровольного резерва не утверждена и не заложена как обязательная.

## Проверки

На работающем окружении:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\check.ps1
```

Проверяет PHP-синтаксис, nginx-конфигурацию, PDO, utf8mb4/InnoDB, HTTP-вывод шаблона, запрет служебных URL и явный 501 неподключённого API. Если Node доступен — синтаксис JS и 11 проверок поведения. Отдельно можно выполнить `node --test tests/*.test.js`.

Результаты и ограничения проверки — [отчёт](docs/verification.md). Локальная демонстрация не является готовым производственным развёртыванием. Официальный nginx/Windows имеет ограничения масштабирования; сервер университета обсуждается отдельно.
