# Предложение сущностей — без создания таблиц

В MariaDB создана только пустая база `pokemon_local`. Ниже — проект для совместной проработки, не миграция.

- **User**: идентификатор, отображаемое имя, email, состояние учётной записи, даты создания/изменения. Источник адреса и политика уникальности уточняются. Пароли и восстановление зависят от будущей авторизации.
- **Role / UserRole**: роли и связь многие-ко-многим. Староста сохраняет роль студента; преподаватель может быть куратором. Одного поля `role` недостаточно.
- **Group**: идентификатор, название, факультет/направление, состояние. Для MVP имя должно быть уникальным в выбранном учебном контексте; правила учебных годов уточнить.
- **GroupMembership**: связь студента с группой и период действия. Демо показывает одну текущую учебную группу, но окончательную кратность связей лучше обсудить заранее.
- **GroupResponsibility**: связь пользователя с группой с типом curator/leader и периодом действия. Предложение: не более одного действующего куратора и одного старосты группы. Приоритет куратора задаёт бизнес-правило, а не копирование роли студента.
- **Request**: автор, название, описание, тип help/event, начало/конец, место, audience mode, nullable positive limit, lifecycle, версия для конкурентного изменения. Состояние набора и количество участий можно вычислять либо хранить с транзакционным поддержанием инварианта.
- **RequestAudienceGroup**: снимок выбранных групп. В режиме free нужен след происхождения данных расписания, доступный администратору, без выдачи чужих занятостей.
- **GroupApproval**: заявка, группа, решение pending/approved/rejected, фактически решивший пользователь, время решения. Уникальность заявки и группы. Нужно согласовать поведение при смене куратора после получения заявки.
- **Invitation**: заявка, студент, группа происхождения, время приглашения, состояние ответа. При пересечении групп не создавать два приглашения одному человеку на одну заявку.
- **Participation / Response**: связь с приглашением, принято/отказано/отменено, временные отметки, версия. Можно объединить с Invitation для MVP. Причина автоматического отказа, если нужна внутренним алгоритмам, не попадает в отчётный DTO автора.
- **NotificationOutbox**: предложение для будущей надёжной почтовой рассылки. Получатель, вид события, дедупликационный ключ, попытки доставки. Сейчас нет ни таблицы, ни писем.

Для отношений — внешние ключи и явная политика удаления. Для участия — уникальный индекс на `(request_id,user_id)`. Для поиска пересечений — индексы по участнику и состоянию с доступом к временам заявки. Обычного уникального индекса недостаточно для запрета пересекающихся интервалов: требуется согласованный транзакционный алгоритм.

Движок InnoDB и utf8mb4 проверены. Предлагается хранить время в UTC и преобразовывать по Asia/Magadan при отображении. Окончательную точность, типы идентификаторов, политики архивирования и историю изменения связей нужно согласовать до миграций.
